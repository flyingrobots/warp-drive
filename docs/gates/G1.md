# Gate G1 — in-memory FUSE fake tree ✅ PASS

**Date:** 2026-05-30  
**Commit:** `25a5f0a` (Docker acceptance harness + gate pass)  
**Runner:** Linux Docker (Docker Desktop on macOS 26.3, ARM64)  
**Command:** `cargo xtask acceptance`  
**Result:** 29 / 29 assertions

---

## Gate condition

> An in-memory FUSE mount exists where `ls`, `cat`, `find`, `rg`, `stat`,
> and `readlink` all return coherent results against a hardcoded tree, and
> writes are rejected with EROFS — before Echo enters the room.

All conditions passed in a single `cargo xtask acceptance` run.

---

## What was proved

### 1. POSIX translation layer works end-to-end

Normal Linux userland tools — `ls`, `cat`, `find`, `rg`, `stat`, `readlink`
— all produced correct output against a FUSE mount backed by an in-memory
`FixtureTree`. No mocks. No stubs. Real kernel calls to a real FUSE adapter.

### 2. `.warp/` surface is visible and readable

The `.warp/` hidden directory and its three files (`coordinate`, `runtime`,
`stats`) appeared in `find` output and were readable by `cat` with the
correct JSON content. The hidden-directory case caught a real bug: plain
`ls` without `-a` omitted `.warp/`, which was detected and fixed during
acceptance runs.

### 3. Inode assignment is stable

`stat /mount/src/main.ts` returned `Inode: 5`, matching the statically
assigned inode in `FixtureTree`. Sequential inode assignment is correct and
stable within a single mount.

### 4. Symlinks resolve through the kernel

`readlink links/readme` returned `../README.md`. Following the symlink with
`cat links/readme` returned the README content — the kernel resolved the
target correctly.

### 5. Write rejection is honest

`echo nope > README.md` and `touch newfile.txt` both failed with EROFS.
The filesystem is read-only at the kernel level, not just at the application
level.

### 6. `cargo xtask acceptance` is the right human interface

One command: build Docker image, run 29 assertions, report pass/fail, exit
0 or 1. The gate condition is mechanical.

## Caveats

- **macOS local mount not passed.** macOS 26.3 (Darwin 25.3.0) did not surface
  the macFUSE 5.2.0 system extension in System Settings → Privacy & Security,
  preventing kext approval. macOS is not the authoritative gate runner; Linux
  Docker is. macOS local mount remains a developer convenience goal.

- **Acceptance script is Linux / GNU userland only.** Uses `stat -f -c '%T'`
  (GNU stat), `fusermount3`, and `/dev/fuse`. Not portable to macOS as-is.
