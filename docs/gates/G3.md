## Gate Condition

G3 passes when `/.warp/stats` reports live operation counters instead of the
G1/G2 static placeholder, `/.warp/runtime` clearly identifies the runtime and
gate, known POSIX operations move the expected counters monotonically, and
existing read-only behavior and write rejection remain intact — for both the
in-memory and echo-rlib runtimes, without breaking any prior gate's own
acceptance command.

G3 does not implement a second Echo-projected file, dynamic Echo-backed
directories, writes, a daemon, or background frontier refresh. It proves that
the membrane can tell the truth about its current read-only behavior.

## What G3 Proves

1. `/.warp/stats` serves a live `MountStats` snapshot on every `read()`,
   not static fixture bytes — for every gate, not just G3 (the adapter
   intercepts the stats inode unconditionally; each gate's CLI path seeds
   the correct `gate`/`runtime` labels for its own diagnostics).
2. Reading `/.warp/stats` does not increment `read_count` (the self-read
   exemption): two consecutive reads of the file report an identical
   `read_count`.
3. The stats inode's content is genuinely live across separate opens, not
   merely correctly-sized: `FOPEN_DIRECT_IO` on that inode plus a zero
   attribute-cache TTL mean a second `cat /.warp/stats` incorporates a fresh
   `open_count`, and `stat`'s reported size always matches the byte count
   actually read through a forced (non-`cat`-optimized) pipe.
4. `lookup_count`, `getattr_count`, `readdir_count`, `open_count`,
   `read_count`, and `readlink_count` move by at least the number of
   distinct, guaranteed-uncached probes performed against them, proven with
   the diagnostics section run immediately after mount, before any other
   command could contaminate the counters via kernel caching.
5. `runtime_observe_count`/`runtime_observe_error_count` are exact, not
   merely present: `0`/`0` for in-memory (no Echo involved), `2`/`0` for
   echo-rlib (one head observation + one query-projected `/echo/head.json`
   observation — the same two calls G2b already made; G3 adds no new Echo
   call, only real accounting of them via `EchoBackend::into_parts()`).
6. `/.warp/runtime` identifies gate, runtime, driver, build mode, and a
   shared `schema_version`, for both runtimes.
7. `/.warp/coordinate`, `/.warp/runtime`, and `/.warp/stats` all agree on
   `"gate":"G3"` under the G3 mount — never a half-updated mount where one
   file reports an older gate.
8. `/echo/head.json`'s own `"gate"` field still legitimately reads `"G2b"`
   under `--gate g3 --runtime echo-rlib` — that is Echo-side payload
   provenance from the query response itself, not the active mount's gate
   identity, and G3 does not touch it.
9. The G1 read/write-rejection baseline and the G2b Echo baseline
   (`/echo/head.json` still a normal read-only projected file) both still
   hold under the G3 mount.
10. Every prior gate's own historical CLI command — bare `cargo xtask
    acceptance` (G1), `cargo xtask acceptance --runtime echo-rlib` (G2a),
    `cargo xtask acceptance --gate g2b --runtime echo-rlib` (G2b) — still
    passes unmodified after G3 landed, proven by rerunning all three
    (29/29, 38/38, 60/60 respectively; see Validation Commands).

## What G3 Does Not Prove

1. A second Echo-projected file.
2. Dynamic Echo-backed directories.
3. Writes, or basis-aware save receipts.
4. A daemon or background frontier refresh.
5. Cache-hit or latency counters beyond the required fields.
6. `.warp/holograms`, `.warp/intents`, `.warp/errors`, or `.warp/cache`.
7. `mmap` of `/.warp/stats` — direct I/O disables shared `mmap` by default
   for that inode.
8. Coherent multi-read snapshots within a single `open()` — every read
   serializes an independent, fresh snapshot (see the design doc's resolved
   decisions on per-read vs. per-open consistency).

## Live Diagnostics Shape

`/.warp/stats` (in-memory example):

```json
{"gate":"G3","runtime":"in-memory","schema_version":1,"lookup_count":9,"getattr_count":11,"readdir_count":3,"open_count":3,"read_count":2,"readlink_count":2,"runtime_observe_count":0,"runtime_observe_error_count":0}
```

Every counter is right-aligned in a fixed 20-character field internally (not
visible above, since `assert_contains`/`json_int_value` in the acceptance
scripts tolerate the padding) — this keeps `/.warp/stats`' byte length
constant regardless of counter magnitude, eliminating any digit-growth /
stale-cached-size race between `stat()` and `read()`.

`/.warp/runtime` (in-memory):

```json
{"gate":"G3","runtime":"in-memory","driver":"warp-drive-driver-memory","build_mode":"debug","stats":"live","schema_version":1}
```

`/.warp/runtime` (echo-rlib):

```json
{"gate":"G3","runtime":"echo-rlib","driver":"warp-wasm","build_mode":"debug","stats":"live","schema_version":1,"worldline":"<64 hex>"}
```

## Implementation Shape

- `warp_drive_core::WARP_STATS_INO`, `WARP_DIAGNOSTICS_SCHEMA_VERSION`, and
  `build_mode()` — the named constants/helper the design doc asked for.
- `warp_drive_fuse::MountStats` (new `stats.rs` module) — eight
  `AtomicU64` counters plus `GateLabel`/`RuntimeLabel`, `Ordering::Relaxed`
  throughout (independent counters, no cross-field ordering requirement).
- `FuseAdapter` gained a `stats: MountStats` field and a centralized
  `live_stats_node(ino)` seam that every stats-aware branch (`lookup`,
  `getattr`, `read`, `open`'s direct-I/O choice) checks — a guessed magic
  inode number cannot succeed if the tree shape doesn't actually back it.
- `warp_drive_echo_backend::RuntimeObservationStats` — real accounting
  returned by `EchoBackend::into_parts()`, incremented at the actual
  `observe_cbor` call sites inside `init()`/`init_g2b()`/`init_g3()`. Fields
  are private with documented getters; the FUSE binary consumes this
  accounting, it does not get to alter the backend's claim.
- `init()`/`init_g2b()`'s existing `.warp/runtime` shape (`"kind":"echo-rlib"`)
  is untouched — their frozen acceptance scripts assert on it. `init_g3()`
  is a new, separate method using a new `runtime_json_g3` formatter.
- The in-memory binary (`warp-drive-fuse`) and the Echo binary
  (`warp-drive-fuse-echo`) both gained/extended a `Gate` CLI flag; `xtask`
  gained a single shared `(Runtime, Option<Gate>) -> Result<Gate, _>`
  resolver (all ten combinations enumerated and unit-tested) used by both
  `mount` and `acceptance`, so the two commands can never disagree about
  what's valid.

## Caveats

1. `/echo/head.json` is still the only Echo-projected regular file — G3
   adds no new projection, only diagnostics around the existing one.
2. `runtime_observe_count`/`runtime_observe_error_count` reflect startup
   observations only; there is no live refresh in G3, so nothing increments
   them post-mount.
3. `/.warp/stats` snapshots are per-read, not per-open — coherent multi-read
   snapshots within a single open are deferred (see
   `docs/method/backlog/cool-ideas/GATE_stats-per-open-frozen-snapshot.md`).
4. The local Echo gate still requires a sibling `../echo-warp-drive`
   checkout before the copy-in Docker image is built.
5. `lookup_count`/`getattr_count` remain non-exact acceptance targets by
   design (kernel/FUSE caching can change totals without changing the
   membrane contract) — acceptance proves lower-bound deltas from bulk
   probes, not exact syscall totals.

## Next Gate Direction

G3 proved the membrane can tell the truth about its own read-only behavior.
The next gate should extend either projection breadth (a second
Echo-projected file, or dynamic Echo-backed directories) or the write path
(basis-aware save receipts) — both explicitly out of scope here, and both
now have a trustworthy diagnostic surface to build on top of.
